🧪 Director Routing 评测约定

Director prompt 只保留框架级硬约束（exact agent_id / flat sequential / each agent ≤ 1 次 / PENDING tail 可改 / [upstream_input_rejected] 协议解析），不带任何 pipeline 模板或 routing 启发。LLM 编排完全靠 sub-agent descriptor 自身的 catalog（purpose / inputs / output）+ stack memory。

所以这一栏看到的分数反映的就是 catalog 单独驱动的能力。想拉分要回到 sub-agent descriptor 或 eval 数据层动，不要回到 prompt 层堆 routing 模板（之前那条路验证过会让 catalog ↔ prompt 互相打架）。

评测口径

  • 数据集：evals/director_routing/eval_cases.json（10 个类别，每条 user_goal + expected_chain）
  • 判分：actual[i] in expected[i] at every slot —— 每个 slot 是允许的 agent 集合，positional set match
  • chain_correct：长度匹配且每一格都命中。step accuracy：每个位置自己的命中率（独立看）。edit distance：set-aware Levenshtein。
  • 下方 "选择运行" dropdown 自动列 Runtime/eval_routing/*.json，每条记录都展示总览 / 分类 / 逐步位置 / 失败模式。

失败模式

每条用例的 expected_chain 是一个有序序列。把每个失败位置归到三类： 漏跑 = LLM 提前停了（这一格本应有 agent 但 plan 没产）； 多跑 = LLM 越界继续（plan 走过了 expected 的终止点）； 错位 = LLM 在这一格选了别的 agent。每个 bucket 内按出现频次排序，括号里给样本 case。
