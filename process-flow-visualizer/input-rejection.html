⚠ Upstream Input Rejection

Consumer sub-agent 在生成时主动拒绝不合格上游输入的机制 —— 19 / 19 已注册 LLM agent（除 4 个 Intake 边界）全部接入。 消除"上游残缺 → 下游硬着头皮编出 plausible 垃圾 → 静默污染整条 pipeline"的 silent-failure 模式。

解决了什么问题

Before Silent failure 模式
  • StoryAgent 输出空 / 残缺的 story_blueprint
  • ScreenplayAgent 在残缺 JSON 上"硬编"出 plausible 但虚构的剧本
  • Evaluator 只查 ScreenplayAgent 自己的 output 形状，过
  • KeyFrameAgent / VideoAgent 基于虚构剧本生成图与视频
  • 用户拿到看似 OK 但实际偏题的成品 —— 故障点已被埋掉
After 结构化 rejection
  • ScreenplayAgent 的 LLM 看到残缺 JSON，主动产 input_rejection
  • BaseAgent.run() 短路 —— 0 retry（同输入必同结果）
  • execution.error 加 [upstream_input_rejected] 前缀 + reason / missing / hint
  • Director replan LLM 识别前缀 → 走 replan-tail 修复上游 producer，而非 retry / skip
  • 故障点被精准定位到第一个出问题的环节，不再扩散

真实 E2E 例子（empty story → ScreenplayAgent）

往 ScreenplayAgent 喂 story_json_text = "{}"，LLM 实际输出（来自 scripts/verify_input_rejection_e2e.py）： 

// LLM 自主产出，被 base_agent._maybe_parse_rejection 解析
{
  "input_rejection": {
    "reason": "Story blueprint contains no narrative substance or character information; cannot create a screenplay.",
    "missing_labels": ["story"],
    "offending_fields": [
      "logline", "premise", "story_arc", "scene_outline", "beats",
      "synopsis", "plot", "cast", "characters",
      "dramatis_personae", "protagonist"
    ],
    "upstream_agent_hint": "StoryAgent"
  }
}

上层 AssistantService 把这个 rejection 翻译成 director 看到的 execution.error： 

[upstream_input_rejected] reason=Story blueprint contains no narrative substance or character information; cannot create a screenplay.; missing=[story]; hint=StoryAgent

对照组（"sparse-but-valid" 一句话 logline + 一个角色）：不触发拒绝，正常产出 3-scene 完整剧本 —— 校准没有 over-reject。

完整数据流

残缺上游 artifact → Consumer LLM → { input_rejection: {...} } → UpstreamInputRejected exception
BaseAgent.run() 捕获 + 短路 → ExecutionResult(passed=False, attempts=1) → execution.error: [upstream_input_rejected] ...
execution.error → Director replan LLM 识别前缀 → action=replan，重跑/替换 hint 指向的 producer

关键约束：rejection 路径强制 0 retry —— 同 input 必同 rejection，retry 只浪费 LLM 调用。重试责任完全交给 director 的 replan-tail（修复上游再重新进入下游）。
