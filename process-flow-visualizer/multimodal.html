🛠️ 工作机制概述

① 多模态输入 + Sub-agent 解耦通信

  1. 2 步 ingestion：用户上传走 POST /api/workspace/upload → 文件写到 inputs/，注册 scope=raw_pending placeholder。
  2. Intake* agent 提升语义：IntakeText（短文本直包 / 长文本 LLM 摘要）、IntakeImage（vision LLM → 视觉描述，caption 标记为"待分类"，同时注册原始 PNG 文件为独立 artifact entry）。
  3. BriefEnricherAgent（有图时）：读 IntakeText 的 brief + IntakeImage 的视觉描述 → LLM 将图片外貌注入 brief text + 分类图片角色（character / location / prop / style）→ 注册 role-specific caption（如"Global character reference image"）→ enriched brief 替代原始 brief 成为 StoryAgent 的输入。
  4. JSON text 透传（CLAUDE.md §7）：所有 sub-agent 的 schema 输入字段都是 *_json_text: str，build_input 用 json.dumps(payload) 把上游 JSON 整块序列化成文本。Agent 的 LLM 自主理解 JSON 形状，零 Python 层 .get() 链。producer 严控自己的 output schema，consumer 对上游零假设。
  5. InputResolver 语义匹配：生产者写 caption（资产属性，不是内容），消费者写 [label] 描述，匹配靠 LLM 读懂语义。新增 modality 只需 IntakeXxxAgent + label 描述。
  6. Materializer 零上游耦合：materializer 只读自家 agent 的 typed output（asset_dict），不读上游 payload。style_notes / must_avoid / semantic_context 等信息由 agent 的 LLM 从 JSON text 提取后写入自家 output，materializer 直接读。

② 多轮任务 / overwrite 是怎么处理的

  1. (task_id, agent_id) 唯一：每对 (task_id, agent_id) 在 workspace 里只有一份 active 输出。同一个 task 里 agent 重跑时，新输出替换旧输出。
  2. 怎么检测到是重跑：完全无状态机 / 无计数器 / 无时间戳。AssistantService.execute_agent_for_task 入口处直接调 global_memory.has_producer_run(task_id, agent_id) —— 扫一遍 append-only global_memory entries，看有没有任何 entry 的 (task_id, agent_id) 跟当前请求的相等。命中 → auto_overwrite = True，没命中 → 走全新写入路径。"事实即检测"：global_memory 里有没有同名产物就是唯一判据。
  3. prune-on-rerun：检测到是重跑后，overwrite_existing=True 一路传到 artifact_writer.persist_execution_from_plan，写新输出前先调 artifact_writer._purge_all_for_producer(execution)，内部用 global_memory.find_by_producer(task_id, agent_id) 找路径，再用 delete_file_at_path 删文件 + global_memory.prune_by_paths(paths) 清 entries —— 同时删掉文件 + global_memory entries。所以磁盘上看不到历史版本。
  4. 为什么不保留历史：因为下游 agent 全靠 InputResolver 的 caption 语义匹配。如果新旧两份产出都在 global_memory 里，LLM 可能挑错版本，或者两份都拿过去吃，下游就看到不一致的上游。"只有一份当前事实" 是 caption-driven 路由能稳定工作的前提。
  5. 用户上传永远保留：raw upload 注册时是 agent_id="user", task_id=""，跟任何 content agent 的 (task_id, agent_id) 元组都不相交，所以永远不会被 prune。重跑只删 AI 生成物，用户的原始素材始终保留在 inputs/ 和 global_memory 里。
  6. 实例：本页 e2e2 v1 video 和 e2e4 phase 1 video 看不到的原因——它们就是被 v2 / phase 2 重跑触发的 prune 干掉的。但 e2e2 的 v1 文本上传和 e2e4 的 phase 1 文本上传都还在 inputs/（因为是用户素材）。
