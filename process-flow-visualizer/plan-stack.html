Plan Stack 工作行为

Director 与 Assistant 之间的持久化桥梁。五张图把工作方式说完：stack 怎么长、 step status 怎么流转、mutation 四种操作的效果、失败时 replan 前后的结构差、Director 的执行循环。

01Stack 结构 ＆ Execution Pointer

按 layer 分层存放 PlanStep；ExecutionPointer = (layer_index, step_index) 指向当前要跑的一步。 pointer 走过的 step 自然"冻结"。

layer 0
IntakeText→ Story→ Screenplay
layer 1
KeyFrame→ Video ▸ pointer→ Music→ Compositor

多层 = 多次 plan：每次新 user turn 或 replan 都调 _persist_plan 追加一个新 layer， 把这次规划的所有 step 挂进去。单次 turn 且无 replan 时，stack 只有一层。

02PlanStep 状态流转

PENDING → IN_PROGRESS → COMPLETED │ FAILED │ CANCELLED

终态三选一。没有"已执行集合" — 一个 step 是否已经跑过，由 pointer 是否走过它来定。

03原子批量 Mutation 的四种操作

所有结构性改动只走 POST /api/plan-stack/modify，整批作为单事务（全成功 / 全回滚）。四种 op 的效果：

create_steps

生成孤立的 PlanStep（尚未进 stack）。

before
∅
after
step_1 step_2

create_layers

追加一个空的 PlanLayer 槽位。

before
layer 0 [ …done… ]
after
layer 0 [ …done… ] layer 1 [ ]

add_steps_to_layers

把已有的 step 挂到指定 layer 的指定位置。

before
step_1 step_2 layer 1 [ ]
after
layer 1 [ step_1 → step_2 ]

remove_steps_from_layers

从 layer 解绑 step（step 对象不删，可再挂）。

before
layer 1 [ step_1 → step_2 → step_3 ]
after
layer 1 [ step_1 ] step_2 step_3
04失败时的 Replan（结构变化）

一个 step 返回 FAILED → planner 产出新的 new_tail → 删光 PENDING tail，追加一个新 layer 承载 new_tail。pointer 随 advance 自然走到新 layer 起点。

before · failure
layer 0
IntakeText→ Story ✗→ Screenplay→ KeyFrame
⇒
remove
PENDING tail
+ new layer
after · replanned
layer 0
IntakeText→ Story ✗
layer 1
StoryRetry ▸ pointer→ Screenplay'

new_tail 为空（LLM 故障 / 没给出 plan）→ 不动 stack，executor 直接 advance 跳过失败步。 总预算由 MAX_REPLAN_ROUNDS 限制，耗尽后锁死 replan，按当前 stack 跑完。
