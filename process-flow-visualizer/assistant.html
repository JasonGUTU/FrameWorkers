🔍 主要失败原因分析（最新一轮）

从 baseline 的 24% 到 Run 5 的 88% 靠 4 轮基础设施修复：schema 瘦身消除 VideoAgent 10.5K 截断 · 显式 max_tokens=65536 破 CF AIG 的隐性 output cap · json-repair + 1 次 LLM parse-retry 救 CJK confusable / 未转义引号 / trailing comma / unquoted key · 修 logger NameError 回归。 剩 3 条挂在 LLM 对 typed schema 的语义合规漂移——evaluator / Pydantic 正确抓到了，但 rework 3 次修不回。

① cr_07 — Screenplay 漏写了临时 NPC 说话人的 character_id
sh_026/sh_039 是 dialogue shot，character_name="Reporter"/"Journalist"，character_id="" 空串。 scene 的 character_locks 只登记了主角 char_001~003，没给"记者"这种剧情里的临时 NPC 留位置。 evaluator 要求 dialogue shot 必须有非空 character_id → LLM 没合法值可填 → 留空 → 挂。3 次 rework 一直重复同一错。
根因：agent prompt 没告诉 LLM 怎么处理"主角外的偶发说话人"——要么动态追加 char_NNN 并回填 character_locks，要么改 block_type 为 narration/monologue。
② bilingual_02 — Compositor 最后一条 transition 的 to_shot_id 写成 null
LLM 输出了 57 条 transitions，最后一条 transitions[56].to_shot_id = null（LLM 可能以为"链路最末没有下一个 shot"）。 Pydantic schema 要求 to_shot_id: str（非 None）→ ValidationError 在 parse_output 直接抛 exception → 跳过 evaluator rework 循环。
根因：base_agent 的 retry/rework 只响应 evaluator 的 L1/L2/L3 结果；Pydantic parse-time 报错直接 raise，没接 retry 路径。chat_json 里的 JSON parse retry 也救不了——JSON 本身合法（null 是合法 JSON 值），挂在类型层。
③ bilingual_05 — KeyFrame L2 stability_keyframes 引用了 L1 global_anchors 里不存在的 location
L1 global_anchors.locations = ['loc_001']，但 8 个 scene 的 L2 stability_keyframes 分别引用 loc_002 / loc_003 / loc_004 —— 6 处违反 L1↔L2 referential integrity。
根因：KeyFrame template + system_prompt 要求每个 scene-level entity 都要在 L1 登记，但 8 scene × 多 location 的规模下 LLM 漏登了 3 个。evaluator 严格 check 抓到，但 rework notes 只说 "references loc_002 not in global_anchors"——LLM 每次 rework 都漏差不多的。 materializer 有 Layer 1.5 backfill 机制可以自动补救，但 evaluator 先否决导致 backfill 永远无机会触发——evaluator 严 vs materializer 宽中间脱节。

治理方向

  • Rework 定向化：evaluator 报错时把定位（哪个 shot / 哪个 scene / 期望值示例）嵌进 rework_notes，不是整段塞 eval_summary。
  • Pydantic ValidationError 接 retry：parse 层失败应该像 JSON parse 一样触发 1 次 LLM 重调——目前完全无 retry 路径，一挂就 FAIL。
  • evaluator ↔ materializer backfill 打通：KeyFrame 的 L1.5 backfill 对缺失 L1 能自愈，但 evaluator 在前面挡住了。可以让"content-semantic"引用完整性检查（比如 L1↔L2 referential integrity）下放给 materializer 阶段处理，evaluator 只保留 LLM 真正能修的语法层检查。
