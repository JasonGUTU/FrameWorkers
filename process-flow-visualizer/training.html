Director Routing LoRA — 训练数据 & 流程

🔥 两阶段 LoRA

① SFT

1,406 samples · 3 epochs · ~530 steps

学什么：从 user_goal 语义到合法 chain 的路由映射；rationale 显式声明"为什么 不 加 XxxAgent"形式的反 bias trace。

Loss：completion-only CE（prompt tokens 标 -100，只对 assistant JSON 算 cross-entropy）。

lr=2e-5, bf16, batch=1, grad_accum=8

➜

② GRPO（hand-rolled, no TRL）

G=4 rollouts/prompt · 3 epochs · β=0.04

学什么：在 SFT adapter 上跑 on-policy rollouts，用程序化 reward 直接拉 chain accuracy。算法 = DeepSeekMath / DeepSeek-R1 风格 GRPO，单步更新，no PPO clipping（importance ratio ≈ 1）。

Reward：format gate（解析失败 / 未知 agent / 重复 → 0），过 gate 后 R = 0.5·pos_correct + 0.5·1[chain_perfect] ∈ [0, 1]。partial credit 防 σ=0 group 信号塌陷，perfect bonus 防 satisficing。

lr=1e-6, bf16 forward · fp32 sampling（NaN guard）

➜

③ Adapter 输出

training/director/adapters_full/

adapters_full/sft/ — SFT 后 LoRA

adapters_full/grpo/ — SFT + GRPO 后 LoRA（最终权重）

推理：infer.py --adapter adapters_full/grpo

📝 数据格式 — 一条 SFT sample 长什么样

每行 {"messages": [system, user, assistant]}。训练时 prompt = system + user，target = assistant。system ≈ 30K chars / ~7.5K tokens（PLAN_UPFRONT_CORE + 当前注册的 22 个 agent 的 markdown catalog；占满 seq_len=8192 的大部分，留 ~700 tokens 给 assistant 输出）；user = 一句 user_goal；assistant = 合法 JSON {"rationale":"...", "plan":[{"agent_id":"...","intent":"..."},...]}。所有 chat template 渲染都强制 enable_thinking=False。

当前活跃数据集 = samples_sft_full.templated.jsonl（1,417 条），由 build_templated_sft_jsonl.py 程序化生成 —— 所有 v3 / overfit_templated sbatch 都用这一份。同目录的 samples_sft_full.jsonl 是早期手写 / teacher-LLM 生成的版本，仅 vanilla train_sft.sbatch 还引用，新实验已经不用。

Templated 数据的关键设计： rationale 全部由 chain-free 骨架模板程序化生成 —— 所有 1,417 条 rationale ≥ 500 chars（均值 844 chars），100% 带显式 Reject 列表（chain 里没出现的 agent 全部一一列出 + 单句理由）。 intent 从每个 agent 的 3-variant 池里按 (slug, idx, slot) 的 md5 哈希挑，不引用 user_goal 的具体词（"Author the story blueprint" / "Render per-shot clips" 这种通用句式）。 rationale 也不混 user_goal 的题材词（"post-apocalyptic" 不会出现在 rationale 里），让 LoRA 学的是 chain shape selection logic —— 看 user_goal 的 trigger 词决定整条 chain，再逐 agent 解释为什么不加其他的 —— 而不是从 user_goal 抄词到 intent。 下面两条都是 samples_sft_full.templated.jsonl 里的真实样本（system 太长省略）。

📐 SFT 数据多样性的三层

① goal: 题材 × 设定 × 角色 × 语言

cultivation / martial-arts / CEO / rebirth / palace / cyberpunk / horror / thriller / sports / rom-com / historical / slice-of-life / mystery / illustrated-storytelling 十几大类，每条 user_goal 再细分情节、角色、地点、语言。

例："Make a cultivation-fantasy animated drama about a sect junior who discovers the revered elder is the demon the sect was founded to purge"

② rationale: 显式反 bias

每条都写"为什么 不 加 XxxAgent"形式的 trace（VideoAnalysis / Ambience / Compositor / 漏 IntakeText 这几类常见误添）。

这是 routing 判断的关键监督信号——不只是链模式，而是每条 agent 该不该出现的 reasoning trace。

③ intent per agent: grounded

每步 8–25 词，必须引用当前 goal 的具体情节 / 角色 / 物件。不能写成 "step for MusicAgent" 这种模板（eval 会把模板化输出当弱信号扣分）。

例："Generate keyframes for the killing-formation's seven layers and the swordsman's progression"

⚖️ GRPO Reward & Loss

Reward 函数（format gate + 部分分数 + 完美奖励）

# Format gate（下面任一条不通过 → R = 0，不再算 chain accuracy） 1. JSON 解析失败 — 直接 json.loads / 去掉 ```json``` fence / 兜底 regex \{.*\} 三轮都失败 2. 顶层不是 object — JSON 解析出来不是 dict（例如返回了 list / 字符串 / 数字） 3. 缺 "plan" 字段 — 顶层 dict 没有 "plan" key 4. plan 不是非空 list — "plan" 是空 list、不是 list、或是 null 5. plan 里有非 dict 元素 — plan 中某一项不是 object（例如直接写了字符串） 6. step 缺 "agent_id" — 某个 plan step 没有 agent_id key，或值不是字符串 7. agent_id 不在白名单 — agent_id ∉ AGENT_REGISTRY（编出来个不存在的 agent 名） 8. agent_id 重复 — 同一个 agent_id 在 plan 里出现 ≥ 2 次 # 其他 NOT 在 gate 里检查（只影响打分，不让 R 归 0）： - rationale 字段缺失 / 不是字符串 → gate 不管 - step 缺 "intent" 或 intent 不是字符串 → gate 不管 - plan 长度跟 expected 不一致 → 影响 pos_correct 分母 - step 里有额外字段 → gate 不管 # Format pass → 在 chain accuracy 上打部分分数 + 完美奖励 pos_correct = n_correct_slots / max(len(actual), len(expected)) # set-aware slot match chain_perfect = 1 if (len 一致 AND 每格都命中) else 0 R = 0.5 · pos_correct + 0.5 · chain_perfect ∈ [0, 1]

为什么不是 binary {0, 1}：G=4 rollouts 在简单题上经常全 0 或全 1，σ(R) = 0 → advantage = 0 → 这一组 prompt 完全没有学习信号（被 group-σ mask 直接丢掉）。partial credit 让"差一点"的 rollout 拿到不同分数，σ > 0，组里能比出高低。

为什么还要给完美一个独立 +0.5 bonus：防止 satisficing — 如果只有 partial credit，policy 学到"稳定 4/5"和"博一把 5/5"在期望 reward 上差不多，会偷懒收敛到 4/5；perfect bonus 让 5/5 (R=1.0) 比 4/5 (R≈0.4) 高 2.5 倍，逼 policy 去搏完美。

实现见 training/director/grpo_reward.py。RewardBreakdown 同时附带 did_parse / all_agents_known / no_duplicate / chain_perfect / got_truncated / n_correct 字段做训练动力学日志（按类别看 format 失败率、截断率、完美链率）。

GRPO loss

# 每个 prompt G=4 rollouts → 组内归一化 advantage μ_i, σ_i = rewards_i.mean(), rewards_i.std() # 沿 G 维度 Â_{i,g} = (R_{i,g} − μ_i) / (σ_i + ε) # sequence-level，整条 rollout 共享 valid_i = (σ_i > ε) # σ=0 的组直接 mask 掉 # Token-level loss（每个 completion token 都进算式，prompt token 全 mask） m_{i,g,t} = aligned_mask · group_valid_broadcast # = 1 当且仅当 t 是 completion 且组 valid L_PG = −(1/N) · Σ_{i,g,t} Â_{i,g} · log π_θ(c_t) · m_{i,g,t} L_KL = (1/N) · Σ_{i,g,t} K3(π_θ, π_ref) · m_{i,g,t} L = L_PG + β · L_KL # Schulman K3 KL 估计器：unbiased、低方差、≥ 0 log_ratio = log π_ref(c_t) − log π_θ(c_t) K3 = exp(log_ratio) − log_ratio − 1 β = 0.04 # KL 锁强度

π_θ = 可训 policy（base Qwen3-8B + SFT LoRA，LoRA 可更新）；π_ref = 冻结参考（同 base + 起步时 SFT LoRA 快照，旁路不更新）。 token-level、不是 sequence-level：每条 rollout 的 advantage 复用到这条 rollout 的每个 completion token 上，loss 对 token 求和再除以总 valid token 数（避免长 rollout 因 token 多就稀释了 advantage）。 无 PPO clipping —— 单步 on-policy 时 importance ratio ≈ 1，clip 没意义。

为什么 KL 用 K3 估计器而不是闭式 KL：闭式 KL 需要对 vocab 全 softmax，token-by-token 算，bf16 下数值容易爆。K3 (Schulman 2020) 只用 log π_θ(c_t) 和 log π_ref(c_t)（两次 gather），数学上 E[K3] = KL、K3 ≥ 0 严格、方差比 naive estimator 低很多。

NaN 防护：之前 TRL-based GRPO 在 bf16 下 multinomial 反复 NaN 崩溃 5 次后被全部移除。当前 hand-rolled 实现 model forward 仍 bf16，但 sampling step 强制 fp32 提精度，梯度走 bf16；logits 在 gather 前显式 .float() 算 logsumexp，防止 bf16 logsumexp 数值不稳。
