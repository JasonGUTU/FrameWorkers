Workspace 存储与读写

Workspace 是 Assistant 的本地运行时存储。职责按 "what / why / when" 切分：artifact_registry 是 "what"（caption + 路径），global_memory 是 "why"（语义决策），logs 是 "when"（操作流），文件本身落在工作目录里。

① 目录结构

runtime_base_path / <workspace_id> /
workspace_global/ ├── artifacts/ # 产物文件落盘根（路径由 LLM #2 编排） │ └── media/ │ ├── StoryAgent/ json/ story_blueprint.json │ ├── ScreenplayAgent/json/ screenplay.json │ ├── KeyFrameAgent/ image/ scene_01_shot_01.png … │ │ json/ keyframes_manifest.json │ ├── VideoAgent/ video/ scene_01.mp4 … │ └── AudioAgent/ audio/ final_delivery.mp4 │ ├── global_memory.md # 语义决策（"why"）—— what / why / context_note ├── global_memory_index.md # memory 的聚合索引 ├── artifact_registry.jsonl # caption 索引（"what"）—— 每行一个 ArtifactRegistryEntry └── logs.jsonl # 操作流（"when"）—— LogEntry per event
关键变化：memory 不再持有 artifact_locations。文件路径由 artifact_registry.jsonl 持有，每条 ArtifactRef 自带自然语言 caption（what / why / scope / path / mime），由 InputResolver 在 Phase 1 用来挑选。

② Workspace 内部模块

dynamic-task-stack/src/assistant/workspace/ · 由 Workspace.__init__ 装配

FileManager

file_manager.py

store_file_at_relative_path / list_files / get_file / delete_file / read_binary_from_uri。统一管理 Runtime/<workspace_id>/... 下所有文件读写。

MemoryManager

memory_manager.py

add_memory_entry（content = {what, why, context_note}，可 supersedes 旧条目）/ list_memory_entries / get_memory_brief。纯语义决策，不存路径。

ArtifactRegistry

artifact_registry.py

append-only：register(execution_id, agent_id, task_id, artifacts=[ArtifactRef]) 写一行到 artifact_registry.jsonl。提供 get_captions_index / get_by_paths 给 InputResolver。

LogManager

log_manager.py

add_log / get_logs。Workspace 把所有 file / memory / execution 操作通过 _add_log 收敛过来，按 operation_type · resource_type · agent_id · task_id · event · execution_id 多维过滤。

AssetManager

asset_manager.py

由 Workspace 注入 5 个回调（store_file / add_log / read_binary / list_files / delete_file）+ register_artifacts。负责 persist_execution_from_plan、hydrate_indexed_assets、collect_materialized_files，落盘后通过 register_artifacts 回写 ArtifactRegistry。

InputResolver

input_resolver.py

懒加载：resolve_inputs_for_agent 调用时构造。读 artifact_registry.get_captions_index + 拼 input_needs_description → LLM #1 → { resolved_artifacts, selected_artifact_paths, rationale }。

③ Assistant ↔ Workspace 读写边界

Workspace 是 Assistant 唯一对外的 facade（service.py 不直接 touch 任何 manager）
Assistant (service.py)
⇄
Workspace facade
⇄
Runtime / <workspace_id> /

READ — Workspace → Assistant

  • get_memory_brief(task_id, agent_id, limit) Director 轮询用：语义决策的薄行视图。
  • list_memory_entries(task_id, agent_id, limit) 完整 memory entry（含 what / why / context_note），Phase 1 注入。
  • resolve_inputs_for_agent(agent_id, task_id, input_needs_description, llm_client, source_text, model) 委托 InputResolver → LLM #1 → { resolved_artifacts: [{what,why,scope,path,mime,payload}], selected_artifact_paths, rationale }。
  • get_workspace_root_file_tree_text() LLM #2 编排路径时用的全库目录树。
  • list_files() / get_file(file_id) FileManager 列举与按 id 读取。
  • get_logs(operation_type, resource_type, agent_id, task_id, limit, level, event, execution_id) 多维过滤操作流。
  • hydrate_indexed_assets(assets) 委托 AssetManager 把 _asset_index.json_uri 展开为可消费 payload。
  • collect_materialized_files(media_assets) 汇总 sub-agent 已物化的 MediaAsset，准备进入持久化计划。

WRITE — Assistant → Workspace

  • store_file_at_relative_path(relative_path, file_content, filename, description, created_by, tags, metadata) 写到 Runtime/<workspace_id>/<relative_path>，自动 log + refresh_file_tree + touch。
  • persist_execution_from_plan(execution, assignments, overwrite_existing) Phase 3 主入口。委托 AssetManager 按 LLM #2 计划批量落盘；返回 (persisted_paths, asset_index, extra_locs)；内部回调 _register_artifacts_callback 把 ArtifactRef 追加到 artifact_registry。
  • log_execution_started(execution) / log_execution_result(execution) 写一条 execution event 日志，自动抽 retry_attempts + eval_summary。
  • add_memory_entry(content={what,why,context_note}, task_id, agent_id, execution_id, supersedes) 追加一条语义决策。不再带 artifact_locations—— 文件路径由 artifact_registry 持有。
  • delete_file(file_id) overwrite 模式下清掉旧版本，自动写 delete log。
