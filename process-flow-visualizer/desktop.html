Workspace 存储与读写

Workspace 是 Assistant 的本地运行时存储。新架构里只剩两份"事实文件"：global_memory.md 是 per-execution 的产物 ledger（每次 agent 跑出来的所有文件都在这里登记，附带 caption / scope），logs.jsonl 是 namespaced event 时间流（execution.* / artifact.* / workspace.*）。文件本身落在 artifacts/ 子树下，由 ArtifactWriter 一次性写入并自动注册到 global_memory。

① 数据流总览

用户 upload → ArtifactWriter 持久化 → GlobalMemory 注册 → 下游 agent 通过 InputResolver 拉数据 → 写 logs 留痕
user upload text / image / audio / video bytes
→persist_raw_upload
ArtifactWriter persist_execution_from_plan
artifact.* events
→register
global_memory.md per-execution ledger
+ per-file caption
artifacts/... JSON · PNG · MP4 · WAV
↑paths
InputResolver (LLM) match captions against
consumer's [label] slots
←get_captions_index
global_memory.md read side
Workspace 内一切产物都先经过 ArtifactWriter，落盘后由 GlobalMemory 注册带 caption / scope 的条目；下游 agent 启动时 InputResolver 把这些 caption 当成"自描述索引"喂给 LLM，让 LLM 决定哪些产物对应当前 agent 的哪个 [label] 槽。没有任何 agent 在 InputResolver 之外直接读 workspace 文件——这就是 caption-driven 的含义。

② 目录结构

_workspaces / <workspace_id> / · 示例：workspace_e2e_text_only_20260413_223748
workspace_e2e_text_only_20260413_223748/ ├── inputs/ # 用户原始 upload │ └── upload_20260413_223748_976438.txt │ ├── artifacts/ # 产物文件落盘根（确定性路径，无 LLM） │ ├── IntakeTextAgent/ task_1_..._exec_1.json │ ├── StoryAgent/ task_1_..._exec_2.json │ ├── ScreenplayAgent/ task_1_..._exec_3.json │ └── media/ │ ├── KeyFrameAgent/image/ *.png │ ├── VideoAgent/video/ *.mp4 │ └── AudioAgent/audio/ *.wav │ ├── global_memory.md # 唯一的 semantic record └── logs.jsonl # 操作流 — namespaced event

③ global_memory.md — entry 格式

每条 = 一次 agent 执行产出的所有 artifact。来自 workspace_e2e_text_only_20260413_223748。
{ "execution_id": "exec_2_4b55623d", // 执行唯一 ID "agent_id": "StoryAgent", // 产出方 "step_id": "task_1_cc5995ea", // 归属 task "created_at": "2026-04-13T22:38:16.151325+00:00", // 写入时间 (UTC) "artifacts": [ // 本次执行产出的文件列表 { "caption": "Story blueprint: 3 scene(s), 1 character(s), Drama, Short Film. ...", // 自然语言描述 — InputResolver LLM 靠它匹配 "scope": "global", // global | scene:sc_NNN | shot:sh_NNN "path": ".../artifacts/StoryAgent/task_1_cc5995ea_storyagent_exec_2.json", // 文件绝对路径 "mime": "application/json" // MIME 类型 } ] }
caption 由 descriptor 的 build_captions() 在 agent 执行完后生成，每个 agent 自定义怎么总结自己的产物。

④ InputResolver LLM 看到的 captions index

global_memory.get_captions_index() 从 entries 派生纯文本索引喂给 LLM。LLM 只看到 #N 编号 + caption + 产出方，看不到路径。
#0 Raw user upload (mime=text/plain). Pending intake processing — only visible to Intake* agents. Produced by user on 2026-04-13 22:37. #1 User-submitted creative brief (228 chars). Pipeline entry point — consumed by story and screenplay agents. Produced by IntakeTextAgent on 2026-04-13 22:37. #2 Story blueprint: 3 scene(s), 1 character(s), Drama, Short Film. Structured input for screenplay generation. Produced by StoryAgent on 2026-04-13 22:38. #3 Screenplay: 3 scene(s), 17 shot(s). Input for keyframe planning and audio scoring. Produced by ScreenplayAgent on 2026-04-13 22:39.
consumer agent 在 input_needs_description 里声明 [label] (single|collection) 槽位。InputResolver LLM 拿着这份 index + 槽位描述，输出每个 label 对应哪些 #N。Assistant 再用 #N → path 映射加载实际文件，组装成 resolved_artifacts 传给 agent。
